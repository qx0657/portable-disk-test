# 产品系列与完整料号

“设备能返回 Model”和“能读到盘身完整零售料号”是不同能力。本应用分别保留它们，不把商品资料匹配描述成从设备直接读取。

## 字段与优先级

| 字段 | 规则 |
| --- | --- |
| 主标题 Model | 使用设备实际返回值；SMART 未给出时使用系统介质名称 |
| 产品系列 | 设备原文中的代码 → 已核实官方目录规则 → 已确认的补充料号 |
| 完整料号 | 设备直接提供的完整代码 → 本地已确认补充；否则显示设备未提供 |

每个展示结果注明“设备报告 / 官方资料匹配 / 标签确认 / 手动确认”。完整料号不会按容量、接口或产品名称拼接。即便官网有某一容量的参考 SKU，也不能直接断言它就是当前实物的地区或包装后缀。

## 目前的官方匹配规则

当前仅为 E82 配置已核实的厂商规则，来源如下：

- SANDISK App **3.4.2 (2717)** 安装包中的 `packages/sandisk_products/assets/products.json`。
- 目录条目 `ssd-extreme-pro-porter`，名称 **Extreme PRO with USB4**。
- [闪迪官方产品页](https://www.sandisk.com/products/ssd/external-ssd/sandisk-extreme-pro-usb-4-portable-ssd)用于对应系列代码 E82。
- 安装包 URL、哈希、目录位置和匹配约束在 [ManufacturerCatalog.provenance.json](../Resources/ManufacturerCatalog.provenance.json)。

| 连接模式 | 匹配条件 |
| --- | --- |
| USB | VID/PID 为 `0781:55C8` |
| PCIe 隧道 | NVMe ID 为 `0781:5030` 或 `15B7:5030`，并且此盘自己的 USB4 外壳 ID 为 `0781:55C8` |

这是一条有出处的系列对应规则，不是完整料号读取功能。只看到通用名称，或只看到一个可能被复用的 NVMe ID，不足以应用 PCIe 规则。

E60 的旧 USB ID `0781:558C` 在该版本官方目录中没有对应项，所以不自动显示 E60。设备原文若明确含 `SDSSDE60…`，或用户确认了标签，则可以展示相应来源。

## 已排查的直接读取路径

在开发验证用 Apple Silicon Mac mini 上，E60 1 TB 和 E82 4 TB 的结果如下。公开资料中不包含实物序列号或 UID。

| 路径 | 观察结果 |
| --- | --- |
| E60 ATA IDENTIFY | 返回通用 Model；附加产品标识字段为空 |
| E60 外壳 SES / SCSI VPD | 可获得名称、内部与外壳序列号、固件等，未找到完整料号 |
| E82 NVMe Identify 原始数据 | 返回 `SanDisk Extreme Pro USB4`，未发现明文完整零售料号 |
| USB / USB4 ROM、IOKit、系统信息 | 有厂商和硬件 ID、产品名称与链路信息，未返回完整料号 |

这些结果只说明当前设备、固件和连接下已验证的路径没有提供完整料号，不证明所有设备都不提供，也不排除未公开的厂商命令。应用不会为寻找料号而升级固件、安装厂商驱动、卸载卷或试探未知写命令。

## 用户补充

闪迪说明产品或包装上可找到型号与料号，见[官方标识位置说明](https://support-en.sandisk.com/app/answers/detailweb/a_id/53002)。

用户可手动照抄完整 P/N，或选择标签近照。本地 OCR 当前识别闪迪 `SDSSDE…` 完整代码；例如 `SDSSDE82-4T00-G25` 只用作格式示例，不预填为任何真实设备的型号。

- 不把 `E82` 或仅有容量前缀的字符串当成完整料号。
- 支持多个候选，要求用户选择、核对并确认。
- 不自动将 O 替换为 0，也不猜地区后缀。
- 输入与已知系列或设备报告值冲突时提示，并要求额外确认。
- 保存来源、确认时间和物理设备身份，保存在当前 Mac。
- 若设备后来提供直接料号，直接报告值优先；原补充记录仍可查阅，冲突不会静默抹去。

新增匹配规则时，应同时更新来源记录、实现、边界检查和本说明，不能仅凭同名产品、可修改的卷名或零散第三方报告放宽匹配。
